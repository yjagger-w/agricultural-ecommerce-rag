# 农业电商智能咨询与 RAG 知识引擎

## 1. 当前已验证版本

项目需求源于此前参与蔬菜业务网站、小程序及真人在线客服时观察到的咨询场景，独立开发农业咨询技术原型。

- 使用 Node.js 与 SQLite 实现商品别名识别和版本化目录查询，按有效日期确定规格、价格及可售状态；过期价格与不可售商品明确降级。
- 实现中英文词法检索式 RAG，按商品、问题类型、确认状态和日期筛选保存知识与 FAQ，记录来源 ID 和标题；将目录事实与知识证据分别路由并合并混合问题。
- 实现最小 JSON/SSE HTTP API 和兼容模型 provider；每个正常模型请求只做一次本地检索与一次 provider 调用。模型仅组织已检索证据顺序，目录价格与规格始终由代码输出。
- 验证 provider SSE 解析、请求与流读取超时、主动取消、客户端断开及错误降级；无证据和纯目录问题跳过模型调用。
- 使用虚构夹具和 provider/fetch stub 完成 38 项离线回归测试，并通过 21 个 JS/CJS 文件语法检查、CLI 导入和空目录实际进程启动检查；另以 24 个虚构问题做本地案例评估，23 例通过，识别出英文查询与纯中文证据间的词法覆盖缺口。验证依据见验收记录和合成案例评估。
- 将本地运行数据、数据库、日志和密钥排除出 Git，并实施有限敏感模式检测；尚未宣称完成真实业务数据脱敏或隐私清洗。

独立性能基准、环境与局限见 [验收记录](validation.md)。合成数据基准不作为业务 SLA。

## 2. 后续目标（计划）

- 基于可公开且来源清晰的农业资料建立正式知识集，设计人工标注的领域评估与错误归因；尚无准确率、召回率或业务效果成果。
- 评估向量与词法混合检索，并在明确数据规模、机器和并发条件后设定响应预算；500 ms 仅可作为后续待验证目标。
- 完善授权数据的人工脱敏流程、隐私审计和防注入评估；现有模式拦截不能替代这些工作。
- 验证真实 provider 的网络兼容性，评估严格证据约束下的自然语言生成，并提供最小演示页面。
- 按部署场景补充认证、限流、运行监控、人工接管和负载测试；当前没有公司部署或生产服务成果。
