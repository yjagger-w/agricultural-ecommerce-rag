# 合成咨询案例评估

本评估使用 `test/fixtures/` 中明确标为虚构的目录和知识卡。24 个手工编写的问题及预期结果在 `evaluation/cases.json`，覆盖目录日期、别名、不可售、政策确认状态、来源隔离、混合问题和英文问法。它们是功能案例，不是来自真实客户的抽样。

## 复现

需要 Node.js 24；无需 API 密钥或外部服务。

```sh
npm run evaluate
npm run evaluate -- --json
npm run evaluate -- --strict
```

脚本在临时目录导入虚构目录和知识，调用实际 `ConsultationService.answer()`，结束后删除临时数据。执行时禁用外部 fetch 和非本机 HTTP；不配置模型，因而仅评估确定性本地回答。默认即使有失败案例也退出成功，方便查看完整报告；`--strict` 在任一案例失败时退出码为 1。`--json` 输出每例预期、实际结果及各检查项，便于后续错误归因。

每例逐项检查路由、商品事实及状态、**全部**证据来源 ID、应出现和不应出现的回答片段，以及零 provider 调用。只有全部满足才算通过。证据来源按多重集合比较，不会把重复来源误判成不同来源。案例预期由虚构夹具人工确定；评估脚本不会把程序输出反填为标准答案。

## 2026-09-27 基线

在本地确定性回答模式下运行得到 **23/24**：

| 类型 | 通过/总数 |
| --- | ---: |
| 目录事实与日期 | 7/7 |
| 知识检索 | 4/5 |
| 商品与来源隔离 | 5/5 |
| 政策确认及过期 | 4/4 |
| 混合问题 | 3/3 |

失败案例 `english-storage`：`how to store tomato` 识别了 `tomato` 商品和 `storage` 意图，但现有虚构番茄保存卡只有中文标题、关键词和正文，词法检索返回零证据，回答“资料不足”。这表明**英文商品别名不自动完成跨语言证据匹配**。下一步可以为有授权的知识卡加入英文关键词或建立经核验的查询词映射，再用独立于开发夹具的案例复测；当前不把这项算作通过。

这 24 例与回归测试共享同一虚构夹具，且由开发者手工编写，不能推算真实农业问答的准确率、召回率、客服效果或生产时延。没有调用真实模型 provider，也没有评估自由生成答案。现有性能数字仍以 `validation.md` 所列独立合成基准为准。
