# 本地数据格式

所有示例数据位于 `test/fixtures/`，均为虚构。运行目录 JSON 不应提交 Git；只将经过授权及人工审阅的数据导入本机。`DATA_DIR` 可指定其他本地运行目录，默认 `data`。

## 目录

文件顶层为 `products`、`versions` 两个数组。夹具另外提供 `fictional: true` 和说明；真实本地导入不要求虚构标识。

| 对象 | 字段 | 约束 |
| --- | --- | --- |
| product | `id`, `name`, `aliases` | ID 为 1–64 位英文、数字、下划线或连字符；名称和别名最多 100 字符，规范化后别名全库唯一 |
| version | `productId`, `version` | 关联已有商品，商品和版本组合唯一 |
| version | `specification` | 非空文本，最多 200 字符 |
| version | `priceMinor`, `currency` | 非负安全整数的最小货币单位、三位大写货币代码；例如虚构的 1200 CNY 表示 12.00 CNY |
| version | `validFrom`, `validTo` | 实际有效的 `YYYY-MM-DD` 日期；开始日包含、结束日不含，同商品区间不得重叠 |
| version | `saleable` | 必填布尔值，不根据模型或知识推断 |
| version | `source` | 必填 `{id,title}`，来源 ID 与标题，不使用本机绝对路径 |

SQLite 实际建立 `products`、`aliases`、`versions` 表、外键及日期查询索引。事务导入失败会回滚整个文件。允许追加新的非重叠版本，不覆盖旧版或商品名称。商品有别名但缺少版本时返回无目录；过期版本不回退为有效报价；尚未生效版本也不作为当前价格。不可售商品不生成可购买报价。

`data/catalog/` 为空保留目录；SQLite 文件实际位于 `data/catalog.sqlite`。应用不会自动导入该目录下的 JSON，必须先运行导入命令。

## 知识、保存说明与 FAQ

顶层 `cards` 数组，字段如下：

| 字段 | 约束 |
| --- | --- |
| `id` | 全知识目录唯一 ID |
| `productId` | 已存在的商品 ID；只有通用资料可以为 `null` |
| `title`, `content`, `keywords` | 标题最多 200 字符、内容最多 2000 字符、关键词文本数组 |
| `kind` | `knowledge` 或 `policy` |
| `facet` | 知识为 `storage` 或 `general`；政策为 `return`、`delivery` 或 `policy`（其他政策） |
| `confirmed` | 布尔值；仅 `true` 可用于回答 |
| `validFrom`, `validTo` | 与目录相同的闭开日期区间 |
| `source` | `{id,title}`；应能在人工作业中定位到原始公开来源 |

源码在启动时加载知识目录内的 `.json`。缺少目录或没有文件表示无知识，正常启动。非法 JSON、重复 ID、过期日期格式、悬空商品关联等使启动失败，不静默加载错误文件。缺少当前有效证据则返回资料不足；未确认或过期政策不用于承诺条件。

商品知识与通用知识严格隔离，通用说明不继承为某商品的政策。一次问题中的多个商品按逗号、分号、句号等分句分别处理；多个商品和不同意图混在同一分句时请求明确对应关系，不猜测归属。暂不跨请求维护会话或代词商品状态。

知识通过中英文分词、字段权重和元数据命中进行词法排序，每个商品与问题范围最多 3 张卡、6000 字符预算。它没有 embedding 或语义模型索引。政策还区分退换与配送，不能互相替代。

## 本地保护与局限

`.gitignore` 排除运行数据、数据库及侧文件、日志、Export、密钥、个人目录和 `.env`。导入验证器拒绝部分凭据形态、Windows 绝对路径等敏感文本；provider 错误不保留网关正文或用户文本。HTTP 不记录咨询内容，也不建立客户或聊天记录数据库。

这不是完整隐私清洗系统：普通姓名、电话号码、业务秘密或未经授权的文字仍需要人工判断。目录及知识来源的真实性、商品关联和政策授权仍由导入者核实。来源 ID 记录不等于来源已经经过外部核验。
